## Amostra e referência

Foram conferidos **35 casos em 14 consultas**, com backend real `d4fd3aa` em
servidor HTTP e SQLite descartável. Nenhum dado da equipe foi escrito.
As entradas são sintéticas, com origem identificada na tela e nos registros.
Não se apresentam os resultados como conferência da operação real SPTrans.

O [caderno de referência](../tests/fixtures/mapas-referencias-us24.json) guarda
contagens, cálculo manual, valor, cor literal esperada, faixa, motivo de
ausência e coordenadas de controle. As expectativas não são copiadas da função
que classifica as cores. `scripts/ensaio_mapa_us24.py` registra as entradas
persistidas e os limites usados na API; o verificador compara a saída com o
caderno e falha se houver diferença.

Rede `00000000-0000-0000-0000-000000000024`; linha `8000-10`; sentido 0;
24/11/2026, **08:00–08:15 America/Sao_Paulo**, equivalente a 11:00–11:15 UTC.
Conjunto `ensaio-us24-1`; cálculo `regra-controle`; correspondência
`correspondencia-controle`. Limites `controle-2026-11-24`, explicitamente
sintéticos, na versão `4d2bb2b0-65b4-550b-94bf-ac0144db5798`.

| Grupo | Conferência |
| --- | --- |
| 8 paradas | 0, 25, 30, 40, 50, 75, 100% e denominador zero; P25/P50 fora dos territórios |
| 4 trechos | 20, 80, 0% e ausência; origem/destino e geometria inteira ao cruzar limite |
| 4 distritos, base paradas | 33,333333%; 21,428571%; insuficiência e território sem registros |
| 3 subprefeituras, base paradas | 27,586207%; insuficiência e ausência |
| 4 distritos, base trechos | 50%; zero; insuficiência e ausência; troca da base preservada |
| Frequência observada | 1 passagem / 0,25 h = 4 passagens/h em P0 |
| 4 distritos, frequência | `AGREGACAO_NAO_SUPORTADA` onde há frequência; demais sem dados |
| Frequência programada | 2 passagens / 0,25 h = 8 passagens/h em P0 |
| Sentido e código | Volta tem 100% em P0, separado do zero da ida; código P25 retorna só P25 |
| 4 consultas vazias | Código/linha inexistentes e os dois limites temporais sem sobreposição |

Exemplos independentes de agregação: distrito 01 = `(2+3)/(5+10)*100`,
**33,333333%**, em vez da média simples 35%. Subprefeitura 01 =
`(2+3+0+3)/(5+10+10+4)*100`, **27,586207%**. P25/P50 ficam fora dos limites.
Um componente insuficiente impede aprovar o agregado como se fosse completo.

O trecho PA–P75 atravessa dois distritos com aproximadamente metade do
comprimento em cada um; a API o vincula ao distrito 01 pela regra de maior
extensão/desempate por código crescente. O verificador confere fração próxima
de 0,5 e extremos originais. O frontend não recorta nem reparte suas contagens.

## Comparação com a tela

Os limites 25/50/75% e 2/4/8 passagens/h usam intervalos com limite inferior
incluído. Assim, 25%, 50%, 75% e 8 passagens/h estão nas faixas esperadas.
O zero recebe azul claro; ausência recebe cinza tracejado, com motivo explícito.
As cores são descritivas e não são uma classificação de aprovação do serviço.

No Chrome, os 35 casos foram comparados com a resposta HTTP: valor desenhado,
cor SVG do preenchimento ou traço, faixa, tabela e legenda com unidade. A
localização é comparada com coordenadas WGS84 de controle; a orientação dos
eixos leste/norte é verificada nos pontos SVG depois da animação do mapa.
Tolerância das coordenadas: 0,000001 grau; limites de polígonos também passam
por uma checagem independente aproximada em metros locais, com tolerância 8 m.
Filtros e áreas sem dados foram exercitados na US24-T03 e nesta conferência.

Os valores de frequência foram persistidos **como referências controladas**;
este ensaio não executa a cadeia de cálculo US15 nem comprova sua publicação
operacional. O teste territorial confirma a limitação atual do contrato em
vez de criar uma média de frequência no navegador.

## Reproduzir

Sem serviço ou banco, com Node 20+:

```powershell
node --test
node scripts/conferir_mapa_us24.mjs
```

Resultado: **146 testes passaram**, incluindo 16 da conferência; 35 casos
conferem nas capturas. O servidor estático tem **3 testes passando**.
Testes de controle confirmam que alterar valor, contagem ou posição faz a
conferência falhar.

Para repetir com HTTP real, usar o Python do backend com suas dependências
instaladas e um checkout que contenha US24-T02 (referência testada `d4fd3aa`):

```powershell
python scripts/ensaio_mapa_us24.py --backend C:/caminho/SprintTimeMarrom-BackEnd
```

Esse processo força SQLite em uma pasta temporária, gera apenas os controles,
inicia API na porta 5000 e frontend na 5173. Os dados são descartados ao encerrar
com Ctrl+C. Não é necessário configurar `.env` ou credenciais. Caso alguma
porta esteja ocupada, escolher `--porta-api`/`--porta-front`; não encerrar
serviços de outras pessoas. O ensaio não é um modo de produção da aplicação.

Em outro terminal:

```powershell
node scripts/conferir_mapa_us24.mjs --api http://127.0.0.1:5000
```

Opcionalmente, no ambiente de QA com Playwright e seu navegador instalados:

```powershell
node scripts/conferir_mapa_navegador_us24.cjs
```

`PLAYWRIGHT_MODULE` e `CHROME_PATH` permitem usar instalações já disponíveis.
Para portas alternativas, passar `--frontend http://127.0.0.1:5184 --api
http://127.0.0.1:5094` ao verificador de navegador; ele encaminha a origem
padrão da API apenas durante o teste. As evidências desta entrega usaram essas
portas alternativas e Chrome 158. O backend e sua configuração não foram alterados.

`--capturar` no verificador HTTP atualiza apenas capturas adicionais da T04,
depois de compará-las com o caderno. Não atualiza referências esperadas.
O hash de cada resposta usa JSON canônico, sem depender de CRLF/LF do Git.
